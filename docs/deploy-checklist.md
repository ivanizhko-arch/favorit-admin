# Что сделать после деплоя. Инструкция администратору

Порядок важен: каждый шаг проверяется до перехода к следующему.
Самое опасное место — шаг 6, до него дойти только после успешного шага 5.

Сервер: `favorit@84.201.152.25`, проект в `~/favorit-admin`,
сервис `favorit-admin`, воркер `favorit-nps.timer`.

---

## Шаг 1. Выкатить и сделать копию настроек

```bash
ssh favorit@84.201.152.25
cd ~/favorit-admin
cp .env .env.backup-$(date +%F)
bash scripts/deploy.sh
```

`deploy.sh` сам делает `git pull`, ставит зависимости и перезапускает сервис.
Новых зависимостей в этой версии нет.

**Проверка.** В конце вывода должно быть `✓ admin service живой`. Если нет:

```bash
journalctl -u favorit-admin -n 50
```

---

## Шаг 2. Пароль админ-панели

Панель открыта из интернета, внутри персональные данные клиентов и
безвозвратное удаление по 152-ФЗ.

```bash
grep '^ADMIN_PASSWORD=' .env
```

**Если там `admin123` — менять немедленно:**

```bash
NEW=$(python3 -c "import secrets; print(secrets.token_urlsafe(24))")
sed -i "s|^ADMIN_PASSWORD=.*|ADMIN_PASSWORD=$NEW|" .env
echo "Новый пароль: $NEW"
sudo systemctl restart favorit-admin
```

Пароль из вывода передать тем, кто пользуется панелью, и стереть из истории
команд: `history -c`.

---

## Шаг 3. Убрать скрытие стадий

Раньше две стадии воронки прятались как служебные, из-за чего суммы не
сходились с Битриксом. Теперь по умолчанию не скрывается ничего, но старое
значение могло остаться в настройках.

```bash
grep -q '^STAGE_SERVICE_IDS' .env \
  && sed -i 's/^STAGE_SERVICE_IDS=.*/STAGE_SERVICE_IDS=/' .env \
  || echo 'STAGE_SERVICE_IDS=' >> .env

grep -n '^STAGE_SERVICE_IDS' .env
```

Должно быть `STAGE_SERVICE_IDS=` — название, равно и пустота.

```bash
sudo systemctl restart favorit-admin
```

---

## Шаг 4. Загрузить данные и сверить

В браузере: `app.favorit-consult.ru/admin` → вкладка **«Дашборд»** →
кнопка **«Обновить из Битрикса»**.

Этот шаг **только читает**, в Битриксе ничего не меняет. Первый сбор на
большой базе занимает до минуты.

**Проверка — обязательная.** Откройте в Битриксе воронку «БФЛ. Сопровождение»
и сравните:

- в панели должны быть **все 17 стадий**, включая «Клиенты от Гараджи»
  и «тех.этап»;
- сумма по колонке «Сейчас» должна совпасть с общим числом сделок воронки.

Если сумма меньше — вебхук видит не все сделки. Он создан под конкретным
сотрудником и показывает только доступное этому сотруднику. Тогда вебхук
нужно пересоздать под администратором портала.

**Дальше не идти, пока цифры не сойдутся.**

## Шаг 5. Посмотреть таблицу менеджеров

Вкладка **«Качество»** → таблица **«Отказы по менеджерам»**.

**Настраивать здесь нечего.** Показываются все, кто встречается в сделках:
уволенные и роботы помечены значками, но не скрыты — их дела никуда не
делись, и прятать их значит терять часть картины.

Отбор делается фильтрами прямо над таблицей, мгновенно, без перезагрузки:

- поиск по фамилии или должности;
- должность — список берётся из ваших же данных;
- статус: все, только действующие, только уволенные;
- тип: люди и учётки, только сотрудники, только роботы и внешние;
- порог доли отказов и минимальное число дел.

Под таблицей — счётчик «Показано N из M» и итоги **по отобранному**,
а не по всей компании.

**Проверка.** Выбрать «Только сотрудники» — «Робот Фаворит» исчезнет из
списка. Нажать «Сбросить» — вернётся.

## Шаг 6. Включить постановку задач

**Самый ответственный шаг: отсюда сервис начинает писать в Битрикс.**

Нужны внутренние ID трёх руководителей. Открыть профиль сотрудника
в Битриксе, взять число из адреса `.../company/personal/user/ЧИСЛО/`.

```bash
nano .env
```

Заполнить:

```
BITRIX_QC_HEAD_ID=       # руководитель отдела контроля качества
BITRIX_SUPPORT_HEAD_ID=  # руководитель отдела сопровождения
BITRIX_CEO_ID=           # генеральный директор
```

Сохранить: `Ctrl+O`, `Enter`, `Ctrl+X`.

```bash
sudo systemctl restart favorit-admin
```

### Первый прогон — вручную, чтобы видеть результат

```bash
.venv/bin/python scripts/nps_worker.py
```

В выводе смотреть на две вещи:

```
"stuck": { "baseline": 217, "created": 0 }
```

Значит накопленные зависшие дела помечены **без задач** — так и задумано.
Разбирать их следует по таблице «Дела в зоне риска» в панели.

```
"refusal_reasons": { "created": 3 }
```

Задачи ставятся только по отказам за последние 30 дней. Если бы не отсечка,
на вашей базе ушло бы около тысячи задач.

**Проверка.** Зайти в Битрикс и убедиться, что задачи пришли нужным людям
и текст читаемый.

## Шаг 7. Закрыть служебный адрес и включить приём жалоб

Можно отложить: понадобится, когда приложение научится отправлять жалобы.
Но правило nginx лучше добавить сразу — сейчас служебный адрес доступен
из интернета.

```bash
sudo nano /etc/nginx/sites-available/favorit
```

Добавить **до** общего правила `location /admin`:

```nginx
location /admin/internal/ { deny all; }
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

**Проверка** — снаружи должно отдавать 403:

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  https://app.favorit-consult.ru/admin/internal/complaints/categories
```

Секрет для приёма жалоб:

```bash
TOKEN=$(python3 -c "import secrets; print(secrets.token_urlsafe(32))")
sed -i "s|^INTERNAL_API_TOKEN=.*|INTERNAL_API_TOKEN=$TOKEN|" .env
echo "Токен: $TOKEN"
sudo systemctl restart favorit-admin
```

То же значение понадобится в `.env` основного сервиса.

## Шаг 8. Включить расписание

```bash
sudo cp scripts/favorit-nps.{service,timer} /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now favorit-nps.timer
systemctl list-timers favorit-nps.timer
```

После этого оценки и жалобы разбираются каждые 10 минут, снимок стадий
обновляется раз в час, отчёт руководителям уходит первого числа.

---

## Шаг 9. Второй фактор для входа в панель

Не срочно, но желательно: панелью пользуется несколько человек, а данные
персональные.

```bash
.venv/bin/python scripts/gen_totp.py
```

Скрипт выведет секрет и инструкцию. Вписать его в `ADMIN_TOTP_SECRET`,
подключить приложение-аутентификатор, проверить до перезапуска:

```bash
.venv/bin/python scripts/gen_totp.py --check <СЕКРЕТ>
sudo systemctl restart favorit-admin
```

Пока секрет пуст, вход остаётся по одному паролю.

## Если что-то пошло не так

**Откатить настройки:**

```bash
cp .env.backup-$(date +%F) .env
sudo systemctl restart favorit-admin
```

**Посмотреть логи:**

```bash
journalctl -u favorit-admin -n 50     # сервис
journalctl -u favorit-nps -n 50       # воркер
```

**Состояние без изменений:**

```bash
.venv/bin/python scripts/nps_worker.py --dry-run
```

**Остановить постановку задач**, если что-то пошло потоком: обнулить
`BITRIX_QC_HEAD_ID` и `BITRIX_SUPPORT_HEAD_ID`, перезапустить сервис.
Задачи перестанут создаваться сразу, данные не потеряются.

---

## Чего не будет даже после всех шагов

**Низкие оценки клиентов** — основной сервис `favorit-app` отбрасывает
всё ниже 8 до записи в базу. Раздел останется пустым, пока не выкачена
правка из `docs/patch-favorit-app-nps.md`.

**Жалобы** — мобильное приложение пока не умеет их отправлять, нужна
правка из `docs/patch-favorit-app-complaints.md` и экран в приложении.

Это не поломка интеграции, а незаконченные работы на другой стороне.
